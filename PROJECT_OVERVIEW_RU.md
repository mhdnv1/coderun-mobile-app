# Описание проекта для работодателя

## Кратко о проекте

Это демонстрационное приложение на Expo / React Native, которое показывает не только верстку экрана, но и базовую архитектуру реального frontend-приложения: авторизацию, защищенные экраны, загрузку данных с API, глобальное состояние, окружения, CI/CD и Docker-сборку.

Проект можно запускать как мобильное приложение через Expo, а также собирать web-версию.

## Что реализовано

### Авторизация и защищенные роуты

В приложении есть экран логина. После успешного входа пользователь попадает в защищенную часть приложения.

Если пользователь не авторизован, он не видит список и страницу деталей.

Авторизация сейчас реализована локально, без реального backend. Это сделано специально для демонстрации архитектуры и работы защищенных роутов.

### Валидация формы входа

На экране логина добавлена базовая проверка формы:

- email обязателен;
- email должен быть корректного формата;
- пароль обязателен;
- пароль должен быть минимум 6 символов.

Если данные невалидны, пользователь видит ошибку под соответствующим полем.

### Работа с данными через локальный API

Для имитации backend используется `json-server`.

Данные хранятся в файле `db.json`, а приложение получает их через HTTP-запросы.

Пример endpoint:

```bash
http://localhost:3001/contacts
```

Это позволяет разрабатывать frontend почти так же, как при работе с настоящим API.

### Redux Toolkit

Глобальное состояние приложения хранится через Redux Toolkit.

В Redux хранится состояние авторизации:

- авторизован пользователь или нет;
- email текущего пользователя.

### RTK Query

Запросы к API сделаны через RTK Query.

Это современный инструмент из Redux Toolkit для работы с серверными данными. Он помогает:

- удобно описывать API-запросы;
- автоматически хранить состояние загрузки;
- обрабатывать ошибки;
- кэшировать полученные данные.

В проекте через RTK Query загружаются:

- список контактов;
- детальная информация по выбранному контакту.

### Список и страница деталей

После входа пользователь видит список контактов.

При нажатии на карточку открывается экран с полной информацией по выбранному контакту.

В карточках длинный текст обрезается через `...`, чтобы интерфейс оставался аккуратным. Полный текст доступен на странице деталей.

### Версия приложения в интерфейсе

Версия приложения берется напрямую из `package.json` и отображается в header.

Например:

```text
v1.0.0
```

Это полезно для контроля версий при тестировании и демонстрации.

### Разные окружения

В проекте добавлены отдельные env-файлы:

- `.env.local` для локальной разработки;
- `.env.release` для release-сборки.

В local-окружении приложение обращается к локальному API:

```bash
http://localhost:3001
```

В release-окружении можно указать реальный backend URL.

### Удобный запуск проекта

Добавлен запуск через `concurrently`.

Команда:

```bash
npm start
```

одновременно запускает:

- локальный `json-server`;
- Expo dev server.

Разработчику не нужно вручную открывать несколько команд для базового запуска проекта.

### CI/CD

В проект добавлены GitHub Actions workflow-файлы.

CI проверяет проект при pull request или push:

- устанавливает зависимости;
- проверяет совместимость Expo-зависимостей;
- запускает TypeScript-проверку;
- собирает release web build.

CD workflow может собрать web-версию и задеплоить ее через GitHub Pages.

### Docker

Добавлен `Dockerfile` для production web-сборки.

Docker-сборка:

1. Устанавливает зависимости через Node 20.
2. Собирает web release.
3. Копирует результат в nginx.
4. Отдает приложение как статический сайт.

Это показывает понимание базового production delivery процесса.

## Что демонстрирует проект как работа разработчика

Проект показывает, что разработчик умеет:

- строить приложение не только на уровне UI, но и на уровне архитектуры;
- разделять публичные и защищенные экраны;
- работать с глобальным состоянием через Redux Toolkit;
- делать API-слой через RTK Query;
- организовывать локальный backend для разработки;
- настраивать разные окружения;
- писать понятные npm-скрипты;
- добавлять CI/CD;
- готовить Docker production build;
- поддерживать проектную документацию.

## Текущие ограничения

Проект демонстрационный, поэтому некоторые вещи сделаны упрощенно:

- авторизация локальная, без настоящего backend;
- release API URL пока указан как placeholder;
- данные контактов тестовые;
- Docker-сборка предназначена для web-версии, не для iOS/Android.

## Возможные следующие улучшения

В проект можно добавить:

- настоящую авторизацию через backend;

## Итог

Это небольшое, но полноценное демонстрационное приложение, которое показывает навыки frontend-разработки на React Native / Expo: от интерфейса и навигации до API-запросов, состояния, окружений, CI/CD и Docker.
